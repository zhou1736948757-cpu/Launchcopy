## 1. API/权限路线（§18.2 决策表）

### 1.1 三路线比较

| 路线 | 工作 | 可进入程度 | 结论 |
|---|---|---|---|
| 可验证公开 API | 用最小实验核实后台四指能力 | 通过证据审查后正常接入 | **本轮未找到可验证方案**（§18.1：不能凭记忆承诺存在公开全局四指 API；Apple 在线资料本轮未取得可用正文，审计 §7） |
| 私有 MultitouchSupport 后端 | 提交 ADR、来源核实、兼容性/权限/退出策略 | 用户明确接受私有后端风险后，才运行采集实验及接入 | **选定**（用户已接受私有路线；风险清单确认后才运行采集实验） |
| 后端仍不可用或用户不接受私有路线 | 完成纯识别器、provider 协议和其他入口 | 四指标为 BLOCKED，不得标完成 | 兜底（不自动触发） |

### 1.2 窄例外边界（§18.2）

- 仅为**获批四指 provider** 允许窄范围私有 MultitouchSupport 例外；**不解除**私有 AppKit/WindowServer、事件 tap、全局键盘监听禁令（§2.2 其余禁止项不变）。
- 不申请 Accessibility / Screen Recording。如需 Input Monitoring：必须独立说明用途、实测依据、拒绝后的功能降级；**未经同意不申请、不自动打开系统设置**（§18.2）。
- 不因为没回调就认定用户拒绝权限（无触摸、无设备、设备类型、ABI 不支持、注册失败都可能产生相似现象）；**设备枚举成功 ≠ 权限已授予**（§18.2；审计 §5.5）。

## 3. 识别会话（§19.2 状态机合同）

- 状态：`Disabled / Idle / Candidate / Recognizing / Fired / WaitingForRelease / Suspended`（可合并，但必须保留可测语义）。
- 合同要点（12 条，T-G-P1 实现依据）：
  1. Idle 收到**恰好四个**有效触点即建立候选（首帧基线；严格四，不沿用参考 `>=4`；无稳定窗口——2026-09-06 实机定案，见 §R-05/R-06）；
  2. 落指不同步不能让第四根手指出现被当作收缩——基线 = 候选段首帧（首帧不判定收缩）；
  3. 从基线计算归一化收缩量；阈值/时间上限**分别命名**（稳定窗口/噪声容忍已随首帧基线模型删除）；
  4. 四指平移不产生收缩；旋转/抖动/噪声不积累成误触；
  5. 五指进入/触点替换/设备改变/数据过期 → 取消或重建候选，不用旧基线；
  6. 触发后锁存 Fired；**同一接触会话无论停留多久只能发出一次请求**；
  7. 冷却只是附加保护，不是重新武装唯一条件；
  8. 全部离面或可靠接触结束才进入可重新武装状态；新手势必须建立新基线；
  9. 四指短暂变三指再变四指不能绕过锁存产生第二次触发；
  10. 缺帧/乱序/非有限数/非法计数/近零初始半径安全拒绝；
  11. Suspend/stop/disable/restart 清掉基线、会话、待派发意图；
  12. **不将「无回调超时」直接等价为全指释放**；后端缺少结束证据时设计保守且可验证的恢复策略。
- 时钟（§19.3）：统一单调时间；后端原始时钟与应用单调时钟若不同须显式转换或保持同一域，**禁止直接相减**。
- 事件身份（§19.3）：会话 generation + 事件 token 用于派发去重与丢弃旧事件；**不记录原始手指轨迹**；低频统计仅识别次数/取消原因/延迟分布。

## 4. 设备隔离（§20.1）

- 回调**保留 device 参数**（参考实现丢弃首参——明确拒绝沿用，审计 §4/§5.3）；设备标识 = 进程内不透明 token，不写磁盘、不跨运行关联（§19.1）。
- **两设备各两指不得组合为四指**（P09 测试）。
- 热插拔/重枚举不得重复注册；旧设备事件不得进入新设备识别器。
- 零触点帧 / device disconnect / cancel 不能被高频压缩逻辑吞掉（P10）。

## 5. 锁序与生命周期（§20.2/§20.3）

- 回调内**禁止**窗口操作、扫描应用、读写布局、同步等待主线程、JSON 编码；确认事件发生时才派发**一次**主线程请求，不为每个触点帧创建 Task。
- 串行队列或窄锁保护状态，**记录选择与积压策略**：start/register、stop/unregister 是否可能同步重入回调；不持有回调所需锁调用可能等待回调返回的系统 stop/unregister；user closure 在锁外调用；缓冲有界且保留 begin/end/cancel（不「只留最新帧」丢重新武装条件）；过载丢帧 → 取消或保守重置，不凭不完整轨迹发 Show。
- teardown 期间 late callback 与已排队主线程事件**同时失效**；主线程消费时也验证 generation、功能开关、进程状态（仅后台 running 检查不足）。
- owner/generation 字段**不是线程安全证明**；Reviewer 必须检查真实锁序与所有权（§20.2）。
- 驻留与隐藏（§20.3）：启用四指入口时**隐藏窗口不能 stop 整个采集服务**（否则无法再次捏合呼出）；隐藏后停止不必要的 UI 帧泵/动画/绘制；四指采集与 UI 动画生命周期分离；真正 Quit/关闭功能/睡眠/会话不活跃时停用或暂停，恢复时建立新 generation；**不在 deinit 承担主要注销逻辑**，不通过永久泄漏库句柄或 callback box 回避安全退出。
- start/start、stop/stop、start-stop-start、退出时异步回调都必须可测（P14/P15）。

## 6. 输入交接（§21.1）

- 识别器发送 `show(source: fourFingerPinch, eventToken:)` 或等价语义；**不得**直接调用窗口 toggle、创建第二个窗口、扫描应用、写布局、绕过协调器状态机。
- 已显示 → 无副作用（不清搜索、不关文件夹、不移走键盘焦点）；正在显示 → 合并为已有目标，不重复启动动画；正在隐藏 → 执行已接受的最新意图策略，旧完成回调不能把新 Show 隐藏；正在 Quit → 拒绝新请求。
- 手势触发但原应用还有手指未离面 → 避免余下触摸立刻在启动器上翻页或点开应用：**有限输入交接，优先基于会话结束**；不全局吞事件、不任意长时间禁用交互；键盘/鼠标不受误伤的测试写入本 ADR 配套验证（P19/M11）；**不能为解决手势残留破坏已验收翻页核心**。

## 7. 默认开关（§18.3/§21.2）

- **用户决策（2026-09-05，`Workflow/decisions/2026-09-05-four-finger-user-decisions.md` 决策 2）：默认开启**——功能实现并验证后，安装即启用四指捏合呼出（无需手动打开）。原锁定值 `false` 被用户决策覆盖；ADR-012 Q1 相应更新。
- 注意：默认开启 ≠ 立即启用；仍须实现完成 + 自动化验证 + 物理门通过后才生效；测试构建可在用户批准后显式启用。
- 状态模型：`Off / Checking / Ready / NoDevice / Unavailable / PermissionNotConfirmed / Suspended`；**Enabled ≠ Ready**——用户打开开关但后端失败时显示事实，保留菜单/Dock/快捷键入口（§21.2）。
- 持久化只写用户开关及获批配置；**不写**触点、设备序列号、原始坐标、后台应用身份（§21.2）；配置迁移遵循现有 schema；设置恢复不自动触发权限弹框或在启动时呼出窗口。

## 8. 私有实现排除方式（§18.3）

**编译排除 vs 运行时禁用必须区分**：

| 方式 | 语义 | 用途 |
|---|---|---|
| 运行时禁用 | 构建含私有后端代码，但开关 false 时不加载/不订阅/不处理旧回调 | 测试构建在用户批准后显式启用；实机验证；功能关闭时零订阅零回调（§16.1） |
| 编译排除 | 以编译条件排除私有实现，产物中**不存在**私有符号/调用 | 面向分发的构建（若未来评估分发）；确保「公开 API 构建中没有私有实现」 |

- 本阶段**分发未评估**：不做商店上架、签名、公证、公开发布结论；私有接口能运行 ≠ 符合分发政策（§18.3）；未来选定分发渠道时单独核查最新要求，不通过隐藏符号字符串、伪装调用或隐瞒权限规避审查。
- 静态红线扫描（§24/§9.10）：获批私有符号只允许**精确模块白名单**（MultitouchSupport 窄例外），不全局取消红线扫描；Docs 中的参考路径允许出现，生产代码不引入第三方品牌或绝对源仓库路径。

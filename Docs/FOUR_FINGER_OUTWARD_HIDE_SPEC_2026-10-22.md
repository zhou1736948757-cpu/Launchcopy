# Optional four-finger outward Hide

Date: 2026-10-22. Status: IMPLEMENTED_VERIFIED_EXCEPT_PHYSICAL_DEVICE_GATE. Human explicitly selected the recommended safe scope, superseding the old inward-only exclusion for this opt-in feature only. Full original goal remains independent LaunchBetter UI/function parity on Launchcopy, not a new input engine.

## Problem / outcome
Provide the counterpart to four-finger inward Show: optional outward resident Hide, defaultOFF. Existing inward parameters/traces must remain unchanged when disabled. No process Quit, cold outward Show, new provider/listener/pump, permission, reference code/assets or global user-state mutation. Preserve accepted folder/main appearance and paging.

## Functional contract
Exactly four contacts with stable identities and valid geometry/time may request Hide after relative radius growth reaches a separately named outward threshold, initially0.15. This is an independent starting calibration, NOT physical acceptance; keep inward0.15/3.5s/0.5s unchanged. Contact-count/replacement/cancel/expiry/lifecycle rejection and one-action-per-contact-session remain. After either Show or Hide, expansion/contraction/reversal cannot fire another action until release. Mode changes invalidate generations/queued events and hold active contacts until release; turning off/on during held contacts must not retrospectively fire. Preserve the old expansion-cancel path exactly when the optional mode isOFF.

Only visible idle main grid or committed Library may Hide. Fail closed for Settings, folder/open/entrance/exit/moveout/inner swipe, main gesture/direct settle/pinned presentation, Library preview/transition, drag, any text editor (including unmarked drafts), IME, sheets/modal, restoration, removal, accepted-write/Quit protection or teardown. Sample admission at first contact and continuously; once inadmissible in a contact session it cannot later Hide when work ends. Recheck before dispatch/effect; unsafe requests are consumed/discarded, never queued for later. ParentOFF disables both while retaining saved optional choice. Enabled is not backend Ready.

## Architecture / interfaces
One existing TouchProvider and existing serialized value recognizer/coordinator. Add `PinchEvent.hideRequested(token:)`. Recognizer has private-set outward mode with `setOutwardHideEnabled(_:)`; `process(_ frame: PinchFrame, allowOutwardHide: Bool = true)` captures/ANDs per-session admission. Coordinator mirrors setter/process parameter; existing `flushPendingShows()` stays source-compatible and handles Shows only. Add `flushPendingHides(allowHide: Bool) -> Bool`: consume bounded pending Hide tokens, validate ready/user/mode/current generation/visible presentation/shared dedup and handoff, accept at mostone, but NEVER mutate presentation or apply window effects. Share action consumption so same token/session cannot Show thenHide. Stop/restart/suspend/provider invalidation clears pending Hide.

Composition passes actual app readiness into process, retains normal Show path, consumes optional Hide, and dispatches through the same resident Hide owner/cleanup, with generation/mode/visibility/admission checks before and after preparation to fence reentrant changes. Default readiness closure false. AppDelegate installs a weak closure checking existing owners; no active real backend in isolated test mode. Production provider replacement/queued callbacks must not acquire a newer owner's generation.

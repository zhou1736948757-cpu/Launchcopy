# Committed icon source invalidation

Date: 2026-10-20. Status: selected bounded correctness maintenance for approved Sources/catalog behavior and the requested whole-code review.

## Problem and outcome
AppID-derived icon identity deliberately survives catalog revisions. When the chosen canonical app URL changes, its cached image and old in-flight load can outlive that source. A queued main-actor delivery can also outlive cache invalidation. Make icons reflect the currently committed source without invalidating unaffected content or changing persistent identity.

## Contract and architecture
- Preserve IconKey, opaque identities, size/scale/appearance variants, cache bounds, loader protocol, cancellation/loadID fences, concurrency limits and MainActor callback delivery. No source path/hash enters keys, telemetry or artifacts.
- IconURLResolver.update returns the set of identities whose URL mapping was added, removed or changed, using in-memory canonical URL equality. Its existing lock protects atomic map replacement and delta calculation. Same URL/no source change returns an empty set regardless of catalog revision, display name, search or arrangement.
- At every catalog presentation commit, use provider.servedSnapshot, never an uncommitted data-source head. Update resolver and synchronously invalidate the delta before external render callbacks request icons. Refresh and search commit paths must share this assembly-owned operation. Direct assembly idle commit also synchronizes before returning for headless/explicit callers.
- IconPipeline.invalidateSources(for:) evicts every cached variant of affected identities, retires their in-flight entries and cancels pending consumers/tasks. Retire ownership under the lock, then cancel tasks outside it so synchronous cancellation handlers may safely reenter the pipeline. Existing loadID ownership prevents non-cooperative old completions from caching or consuming replacement listeners. Unaffected hits/loads remain.
- Register already-accepted queued deliveries under the same pipeline lock that accepts cache hits or finishes a current load. Invalidation removes affected queued delivery receipts. MainActor delivery takes a receipt before callback; removed receipts cannot call back. Do not hold pipeline locks across UI callbacks. A callback already admitted before a concurrent invalidation wins its own linearization point; integrated commits/callbacks are MainActor-serialized.
- Track only actually queued delivery consumers, not a source-generation tombstone/history dictionary. Existing cancellation-after-delivery semantics remain; shutdown clears queued receipts and refuses new work. No per-frame processing, image persistence, source stat or new background workers.

## Scope and non-goals
Only pipeline source invalidation/delivery receipts, resolver+assembly commit wiring, the existing AppDelegate search commit call, and deterministic tests. Same-path content updates, NSWorkspace caching, identity redesign and multi-instance freshness are separate policies. No PagingCore/PagingUI/handfeel, schema/default/organization/UI change. No source-reference access, formal data mutation, manual application move, app restart/install/sign/commit or OS action. The Library cold-entry hitch remains user-deferred/non-blocking with CPU causality unproven.

## Acceptance and verification
Generated in-memory colored images, injected scanners/loaders and continuation/expectation gates only. Use an internal lock-protected processed-result acknowledgment to gate old finish ownership decisions, not merely loader return or negative callback timing. Its scalar is per-result only, read-only externally, and does not affect policy or expose identities/clock data. Cover cache variants and unaffected hits, non-cooperative old success before/after replacement, queued old cache-hit/finished deliveries, shutdown/cancellation, resolver added/removed/changed/no-op deltas, served-versus-pending authority, refresh and search commit integration, same URL revision/name stability and remove/re-add. No real app icons or files. Demonstrate old baseline integration failure where feasible; focused pipeline/integration and full tests serially, Debug/Release unsigned isolated package and diff check, stable source hashes. Independent bounded review after freeze; source/tests do not imply native visual/performance acceptance. Existing automated suites may use their own temporary fixtures.

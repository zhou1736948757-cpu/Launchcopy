## Integration decision in one paragraph

Use **one app-owned readability result and one composed visibility/input mask** for the existing main surface. Resolve it from the applied capacity, applied appearance, actual page bounds and unobscured content bounds. Preserve the mounted Surface, its logical count, query and selected identity. Suppress its drawing, grid actions and AX exposure together when insufficient; show a separate localized, accessible message below search. Do not make readability a prerequisite for accepting/applying capacity: otherwise an unreadable 8×8 grid could never apply the user's corrective 3×3 choice. Folder and Library readiness/presentation remain independently owned.

## 3. Readability policy: exact line-box math and bounded assessment

`GridItemContentGeometry` (`GridItemAppearance.swift:28–66`) is authoritative. With cell width `w`, height `h`, and a valid appearance, let `L` be the full name-line height from an **uncompressed reference instance** of that geometry:

- Default 11pt name font: `L = 14pt` by explicit compatibility rule.
- Other fonts: `L = ceil(NSFont.systemFont(ofSize: size).ascender - descender + leading) + 1`, not the font point size. Write `L16` for the actual 16pt result; its numeric native value was not executed/measured here.
- Full count line is the geometry's uncompressed 12pt box; the cell uses a separate 10pt count font (`AppGridCellView.swift:168`). Do not apply the name font size to count height. Native text baseline/glyph clipping still needs inspection; these are line-box guarantees, not pixel-level typography certification.

For visible Folder captions and full lines, fitted side is `min(preferredIconSide, w, h - L - 26)` once sufficient height exists: 12pt top + 2pt caption gap + 12pt count + `L`. The 24pt floor therefore needs **`h >= L + 50`, `w >= 24`, positive name/count widths, full `L`/12pt heights, finite contained frames**. Checking merely `nameFrame.height > 0` accepts truncated lines and is wrong. Use a generous-height reference geometry to detect the compressed line boxes; do not measure the already-compressed cell and call that its required height.

For apps alone the vertical floor is `h >= L + 38`. The approved policy is conservatively Folder-aware, even when the current visible results contain only apps. For hidden labels, neither name nor count reserves height: `side = min(preferredIconSide, w, h - 12)`, so `h >= 36` is sufficient vertically. Do not fail hidden-caption mode because intentionally unused caption frames are compressed. Icons, bounds and hit targets must remain finite/contained in both modes. Horizontal truncation of names/count strings is permitted; full untruncated arbitrary user titles are not promised.

### Supported content bounds and testable policy API

Do not introduce a guessed global “minimum window = 700×500” rule. The accepted protection makes support conditional per shape/appearance. The examples1000×700 and1470×956 come from startup sizing/fallback, not an enforced native minimum or a measured screen.700×500 is a deliberate compact assessment point.

Proposed policy contract (names advisory; agree placement with the domain worker):

```swift
MainGridReadabilityPolicy.resolve(
    pageBounds: CGRect,
    unobscuredBounds: CGRect,
    capacity: MainGridCapacity,
    appearance: GridItemAppearance,
    showsLabels: Bool,
    mode: AppGridLayoutMode,
    committedPageItemCount: Int
) -> MainGridReadabilitySnapshot
// Snapshot: canPresent, limitingReason, minimumFittedFolderIconSide,
// requiredNameLineHeight, actualNameLineHeight, actualCountLineHeight.
// Reasons: invalidBounds / insufficientGlyph / clippedCaption / obstructedContent.
```

Pass validated capacity; reject nonfinite/degenerate viewport inputs as unavailable instead of relying on incidental CGRect NaN behavior. Use actual `AppGridGeometry` and `GridItemContentGeometry`; a bounded scan of at most64 hypothetical slots is sufficient at a geometry boundary. No catalog/disk/icon work is required. In ordinary mode assess the full selected shape, including on empty/partial pages, so the same capacity does not become “readable” because its last page happens to be sparse. In search use its real occupied-row geometry and selected columns, conservatively with Folder caption budgeting; do not modify search row placement solely to simplify the policy. For zero search results use a deterministic single-row probe to avoid returning readable for an invalid viewport; no stale cells become exposed.

`pageBounds` must be exactly what the renderer uses. Separately derive `unobscuredBounds` in the same coordinate space from root safe-area insets and the **resolved** search frame (below `searchFrame.minY - 12`), and check the actual glyph/caption stacks fall inside it. Do not feed a cropped “usable” rect into only the policy, which would double-subtract96/24 and disagree with the rendered grid. Main may instead choose a shared new bounds resolver, but then renderer, drag and dots must use that resolver together. Current main geometry ignores safe-area insets; the Folder resolver (`refreshFolderLayoutIfReady`, `AppDelegate.swift:1825–1844`) already demonstrates correct safe-area/search exclusion. Include nonzero origins and host coordinate conversions in tests. Count/name widths must be positive; do not require full arbitrary string widths.

Language is not a reason to reload icons or change the grid font. `presentLanguage` must relabel and lay out the protection message, and revalidate its available region; current grid line metrics themselves are language-independent system-font metrics. If message size participates in a protection layout result, key/invalidate that result by displayed language as well. Search/settings/message usable area needs a separate native support check: arbitrarily tiny/zero-sized windows cannot physically display all three. Existing code sets no enforced content minimum, and this advisory does not authorize resizing one.

Keep the policy deterministic and free of lifecycle decisions. Where injecting line metrics is necessary for pure tests, inject the **same metrics abstraction used by content geometry**, or test on MainActor with actual AppKit fonts; do not maintain a second table of guessed font heights. Source tests `GridItemAppearanceTests.swift:60–68` already compare actual system line metrics; they do not supply a recorded numeric `L16`.

## 4. Capacity admission, recompute, and exact wakeups

Separate three concerns: accepted persistence receipt; queued safe capacity transaction; current readability mask. Size/appearance can make the existing grid unsafe immediately even while a **new capacity** is deferred. Conversely, an insufficient grid must not block a safe capacity transaction that fixes it.

Capacity readiness should retain the existing scalar appearance gate (`AppDelegate.appearancePresentationIsReady`, `:2359–2370`) and add any open Folder, any retained entrance/exit, Library open/return ownership, native text/IME/edit ownership, menu tracking, settings recording/source panel ownership, attached sheets/application modal, restore/Quit, applying guards and an unpinned terminal outer state. Do not reuse `canCommitWorkspaceLayout` or require the launcher key window: settings Apply naturally makes the settings window key. Ordinary active search text need not be destroyed or block forever; marked text and actual edit/command callbacks defer, then preserve the same editor/caret when safe. Folder title/alias editing retains its stricter exclusion.

## 5. Resize/gesture/Folder conflicts and transaction order

1. **Readable resize during outer gesture:** current `PagingSurface.layout` (`:929–946`) rebases width through Core, and Core `setPageWidth` (`:305–333`) preserves tracking or restarts settling. Keep this behavior. Current `windowDidResize` cancels direct navigation and pointer drag, not all outer gestures. Recompute availability from the **applied old shape**; keep pending capacity deferred until pin/gesture/settle ends. Do not change rows halfway through the rebase.
2. **Resize crosses into insufficient space:** hide/mask top-level content/input immediately at the layout boundary; cancel an existing top-level pointer session and revoke B1 replay before future mouse-up. A swallowed outer scroll sequence cannot simply be abandoned with a live pin: use the existing `surface.cancel()` once on this availability transition when outer activity needs terminating, outside a Core callback/reentrant apply stack, and verify pin/driver settlement through the existing callbacks. Do not modify Core physics. Consume residual momentum/drag/up from that discarded sequence and require a fresh begin before accepting trackpad input again if the window immediately grows; otherwise old momentum can reenter the restored grid. Legacy phase-less wheel events need an explicit independent policy in owner tests. Surface `cancel()` does not itself call `clearPendingFinish` (`:356–361,:558`), so no source-only claim of full pending-input reset is warranted; test the pending-ended/timeout/new-begin combination. Report a seam insufficiency to Main rather than editing frozen private state.
3. **Resize while Folder is open:** retain existing drag/motion cancellation and independent `refreshFolderLayoutIfReady`; update outer readability without changing its logical capacity or closing Folder. Folder members/title/scroll keep their own availability. On Folder close, outer insufficient-space message appears; the new capacity may drain only after logical close **and** retained exit completion. A protected outer grid offers no move-out target; keep member-only operations independent.

## Decision

**One concrete approved-contract discrepancy remains in this scope:** the Library folder-assignment sheet does not apply the existing destination-choice rules. `AppDelegate.swift:2443–2447` always adds Move to main pages, then enumerates `layout.folders` with raw titles. It does not exclude the selected app's current folder, follow `topLevelOrder`, or distinguish duplicate titles. The grid context-menu implementation correctly does all three. This is a bounded source finding, not a native reproduction or an assertion of corrupted persistence. See F1 below.

The latest native evidence materially closes earlier acceptance gaps: **66cd55c1** automatically updates results on real healthy-root install/remove events; a real metadata-event-plus-root-park transaction produces degraded coverage, preserves query/layout bytes, remains conservatively degraded after return, and recovers via Refresh Now. The same candidate actually launches the controlled executable from a grid click and Library Details Open. These observations must replace old blanket claims that source loss or real launch has never been exercised. They do not prove universal RootChanged delivery, populated-group retention on this empty-root profile, every app's compatibility, or the full native interaction matrix.

The earlier real workspace/Library failed-save → default Cancel → retry → process-restart transactions are **already demonstrated on 889d6613**, not missing historical observations. The repair changed only the source coordinator and its tests relative to that baseline; this preserves useful component evidence but does not turn an older executable's GUI transaction into a new 66cd55c1 observation. No blanket rebuild or repetition of the old audit is warranted.

## Concrete missing requirement evidence

### E1 — Combined IME command routing is unproven

**Evidence:** `AppLibraryViewTests.swift:324–332` asserts marked text exists before direct `view.handleEscape()` and only checks no Back afterward. It does not assert composition was canceled, committed text/query preserved, details preserved, or subsequent Escape priority. Return/Down tests at lines 126–143 use an unmarked standalone `NSTextView`. The window-route test at `AppLibraryLaunchAndQuitTests.swift:119–135` has no mounted Library/editor and substitutes its Escape callback.

**Affected requirement:** composition/editor cancellation before navigation, and query Return/Down must not leave the IME candidate interaction to select/open a result prematurely.

**Bounded evidence needed:** exercise marked Return/Down through the actual mounted search editor/delegate and ensure selection/open/Back do not occur; then exercise the window Escape path with that editor and confirm the correct layer changes, including continuation after composition cancellation. Finally validate an actual input method's candidate selection/commit/cancel in the real candidate. Synthetic `setMarkedText` cannot certify input-method behavior. This is a coverage gap, not evidence of a broken input method.

### E2 — Native Tab traversal and category-control focus transitions are unproven

**Evidence:** `testTabCommandsStayNativeAndEmptySearchReturnDoesNotOpen` at `AppLibraryViewTests.swift:145–154` only asserts direct search delegate calls return false for Tab/Shift-Tab. It never traverses mounted controls or asserts a visible destination. The layout test at lines 356–371 checks frames, details visibility and compact-picker hidden state without putting either category control into focus.

**Specific source risk:** `AppLibraryView.swift:311–317` alternates the compact picker and category-scroll visibility at root width 444 (`bounds.width - 24 < 420`). The explicit focus repair at lines 329–330 handles only the result table hidden by drawer details. `preferredFirstResponder`/`owns`, lines 157–174, accepts descendant ownership without checking hidden ancestors. If AppKit leaves a category table/picker as current responder during a width transition, that hidden responder is still preferred. `AppSearchController.swift:265–273` uses the mode provider without independently checking visibility. No reviewed test establishes whether AppKit automatically repairs either direction.

**Affected requirement:** keyboard focus and native Tab must remain on the available Library controls. This is concrete missing behavior evidence, not generic visual polish. The absence of explicit remapping alone does not prove a native defect.

**Bounded evidence needed:** focus the wide category table, resize to compact and inspect actual first responder/hidden ancestors; repeat from the compact picker to wide. Traverse Tab/Shift-Tab through mounted search, category, results and explicit details controls at both layouts, including return from details and key-window reacquisition. Assert focus never remains in a hidden subtree and no command leaks into the hidden grid. Any implementation repair is conditional on the result; none is presumed here.

### E3 — Accessibility action semantics lack mounted accessibility-path evidence

**Evidence:** the reviewed tests call ordinary `performClick`, direct selectors/callbacks, or `keyDown`; the only explicit accessibility assertions are identifiers at `AppLibraryViewTests.swift:351–353`. No reviewed test asks the mounted controls for accessibility actions/roles/children or invokes an accessibility action. Native AppKit control classes and localized labels are positive source evidence, but ordinary button clicks do not demonstrate AX press delivery or VoiceOver navigation.

**Affected requirement:** the approved native accessibility/VoiceOver gate and access to the existing entry, filtering, details, Open/Reveal and management actions with the same validated semantics.

**Bounded evidence needed:** inspect the actual exposed mounted hierarchy and existing native actions; invoke supported control actions through their accessibility interface and verify the same request/admission path, enabled/disabled behavior and hidden-control exclusion. Inspect row selection and explicit Details/Open separately; do not require a new custom row action absent from the approved contract. Confirm VoiceOver navigation, control names/destinations and action behavior on the actual candidate. This report finds no proven missing custom action and requests no broadened feature approval.

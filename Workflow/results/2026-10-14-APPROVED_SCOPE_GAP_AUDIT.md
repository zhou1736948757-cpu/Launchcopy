## Bounded source concern requiring reproduction, not a new feature

`AppDelegate.layoutSearchField()` currently calls layoutActionFeedback before
updating search.field.frame. layoutActionFeedback anchors its vertical position to
that field's minY. Resize and screen-change delegates call layoutSearchField.
Therefore a geometry update that actually changes the field's top inset can leave
the feedback aligned to the prior field frame until a later presentation/layout
callback. Autoresizing may already align ordinary resizes; this source observation
is NOT a confirmed real screen defect or an observed GUI regression.

Next safe code action: reproduce with an unshown actual search/notice/window fixture
and assert final relative geometry after the real delegate seam, including a
screen-safe-area change if a sanctioned injection seam is needed. Only if the
regression fails, move dependent chrome layout after the search frame update within
the existing MainActor boundary. Preserve missing-search behavior and no deadline/
query/identity/input/physics changes. Do not change formulas merely to make a fixture
pass or report this as a new functional gap without runtime/behavioral evidence.
